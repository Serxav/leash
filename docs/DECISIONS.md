# Decision log

Every important technical decision, in plain words, so Sergi can explain each part of the
project. Newest at the bottom.

**Format.** Each entry has an ID and a date, then:
- **Decision:** what we chose.
- **Alternatives:** what else we considered.
- **Why:** the reason.
- **Status:** accepted, pending or replaced.

---

### D-001 · 2026-10-14 · Repository protection from day one

- **Decision:** public repo `Serxav/leash` with the MIT licence and the Node `.gitignore`.
  - `.claude/settings.json` denies Claude Code read/edit access to `.env` and `.env.local`,
    and is the only direct commit to `main`.
  - A ruleset on `main` blocks deletion and force pushes, and requires a pull request
    (0 approvals) and linear history, with no bypass actors.
  - Only squash merge is allowed, and branches are deleted on merge.
  - Secret scanning, push protection and Dependabot alerts are enabled.
- **Alternatives:** classic branch protection; protecting `main` later.
- **Why:** the hackathon rejects leaked secrets and broken demos, and every change should
  pass CI before reaching `main`. Rulesets are GitHub's current mechanism and also block
  admins.
- **Status:** accepted. Follow-up: add the CI check as a required status check once
  `chore/setup-ci` is merged.

### D-003 · 2026-10-15 · Node 24 LTS

- **Decision:** pin Node **24 LTS** in `.nvmrc`, in the `engines` field of `package.json`,
  in CI and on Render.
- **Alternatives:** Node 26, which is installed locally but is still "Current", not LTS.
- **Why:** LTS versions have the widest support from Render and from native modules
  (`better-sqlite3` ships prebuilt binaries for LTS versions). The same version everywhere
  avoids "works on my machine".
- **Status:** accepted. Node 24 must be installed locally before `chore/f0-scaffold`.

### D-004 · 2026-10-15 · Gemini development model pinned

- **Decision:** while `AI_PROVIDER=google` (until Nov 1), use `gemini-2.5-flash`. Verified
  available on our key on Oct 15.
- **Alternatives:** `gemini-flash-latest`.
- **Why:** a `-latest` alias can change behaviour without notice and break tests. A pinned
  model gives reproducible results.
- **Status:** accepted.

### D-005 · 2026-10-15 · Project skeleton tooling

- **Decision:** create the app with `create-next-app`: Next.js App Router, TypeScript,
  Tailwind and ESLint. Then add Vitest, Zod and Drizzle ORM with `better-sqlite3`.
- **Alternatives:** a hand-made setup; other databases (Postgres).
- **Why:** this is the official, well-documented starting point, and it matches the brief's
  stack. SQLite needs no external service and survives until Dec 15 if demo data is
  re-seeded at boot.
- **Status:** accepted. The `better-sqlite3` install is verified locally and in CI during F0.

### D-007 · 2026-10-15 · Sponsor tools strategy

- **Decision:** use every sponsor tool that genuinely fits, and none before the MVP core is
  done. From the official prize table (verified Oct 15), only **AG Grid, APIMatic, Bryntum,
  Channel3 and Render** have prizes.

### D-008 · 2026-10-15 · "14-day return window" wording

- **Decision:** label the 14-day countdown in the UI as a **"14-day return window"**.
- **Alternatives:** "14-day withdrawal right".

- **Status:** accepted.

### D-009 · 2026-10-15 · Claude Code works in manual permission mode

- **Decision:** Claude Code sessions for this repo run in manual ("Ask permissions") mode.
- **Alternatives:** auto mode.
- **Why:** the deny rules in `.claude/settings.json` block Claude's file tools and common
  shell readers (`cat`, `head`…). According to the Claude Code docs, they do not block every
  indirect read, such as a script that opens the file itself. Reviewing each command is the
  real safeguard. CI also runs gitleaks.
- **Status:** accepted.

### D-010 · 2026-10-15 · Scaffold details (Next.js 16)

- **Decision:**
  - The app was generated with `create-next-app@16.4.1` in a separate folder, and only the
    needed files were copied in. The template's Vercel/Next.js logos and links were
    removed, because the UI must have no third-party brands.
  - Next.js 16 defaults are kept (`cacheComponents`, Turbopack).
  - `better-sqlite3` is pinned to an exact version (13.0.3). It is the only package whose
    install script npm is allowed to run (`allowScripts` in `package.json`), because it
    compiles a native module.
  - `typecheck` runs `next typegen` before `tsc`, because Next.js 16 generates route types
    such as `LayoutProps`.
  - The Vitest configs are `.mts` files (ESM), as Vite recommends.
- **Alternatives:**
  - Generating into the repo directly. Refused, because it would overwrite our README and
    `.gitignore`.
  - Node's built-in `node:sqlite`, which needs no compile step. Drizzle 0.45 has no driver
    for it.
- **Why:** a clean, reproducible scaffold, with no brand assets and the smallest set of
  install scripts.
- **Known issue:** `npm audit` reports 5 high-severity findings (a `braces` DoS issue)
  inside `eslint-config-next`. This is a lint-only dev dependency that is never shipped to
  the server or the browser. npm's suggested "fix" downgrades to Next 14, which is wrong.
  We will update when `eslint-config-next` publishes a fix (Dependabot will notify).
- **Status:** accepted.

### D-011 · 2026-10-15 · The server refuses to start on an unsafe configuration

- **Decision:** `src/instrumentation.ts` validates the environment once at server start
  (`src/config/env.ts`, Zod).
  - If `PAYPAL_ENVIRONMENT` is not `SANDBOX`, or the selected AI provider's key is
    missing, it logs the problem and **exits the process** with code 1.
  - Error messages contain variable names, never values.
  - `assertSandboxApiBase` only allows `https://api-m.sandbox.paypal.com`. The PayPal
    client (F0 task 4) will call it before every request.
  - `CHANNEL3_API_KEY` is optional, because the local catalog is the fallback.
- **Alternatives:** throwing inside `register()` only. Tested: Next.js then keeps the
  process alive and answers every request with HTTP 500, which is not "refusing to start".
- **Why:** the brief requires that live PayPal can never be used, even by mistake.
- **Status:** accepted. Tested with `next start`: sandbox config → `/api/health` 200;
  `PAYPAL_ENVIRONMENT=LIVE` → exit code 1; `AI_PROVIDER=anthropic` without a key → exit
  code 1.
